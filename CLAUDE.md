# Vroombrite — project notes

Website for **Vroombrite**, a doorstep car and bike wash/detailing business in Mumbai run by Aniket Gurav. "Vroombrite" is the working brand name. The repo lives on the `littlegasp` GitHub account for now and will be transferred to the brand's own account later.

## Stack
- Plain static HTML/CSS/JS, deployed with GitHub Pages from the root of `main`. `.nojekyll` is present. No framework; this was chosen over Next.js.
- Data lives in **Supabase** (project `rcekecnigbtgicvntfbz`, Mumbai region). Schema, security and functions are in `supabase/migrations/` (run in order: 0001 init, 0002 fixes, 0003 staff tools, 0004 Studio screens, 0005 slots/days off + job photos, 0006 timer/checklist/customer notes/move day, 0007 plans & societies, 0008 pay/expenses/stock/receipts/cancel reasons/push, 0009 track page/cash handover/due fixes, 0010 left-over jobs); test locally with `supabase/test/stub.sql` + `test.sql` + `test_0003.sql` … `test_0010.sql` on plain Postgres. Publish an app change only after its migration has been run in Supabase. The site and staff app call database functions (`/rest/v1/rpc/<fn>`) with plain `fetch`, no libraries. All tables have RLS on and no direct grants; anon may only call `check_offer`, `create_booking`, `submit_enquiry`, `submit_society_lead`, `submit_review`, `public_reviews`, `sheet_copy`, `slot_availability`, `public_receipt` (needs the booking's random `receipt_key`), `public_track_link` (website, same phone, within 30 minutes), `public_track` and `public_change` (both need the booking's random `track_key`).
- Slot limits: `slot_caps` (website bookings per slot per day, null = no limit), weekly days off in `app_settings.closed_weekdays`, one-off `closures`. A trigger refuses full/closed slots only for `source = 'website'`; staff bookings just get a warning. Slot names must stay in step with `SLOTS` in `src/app.js`.
- Job photos: private Storage bucket `job-photos` (`<booking id>/<before|after>-<stamp>.jpg`, JPEG ≤3 MB, shrunk to 1280 px in the browser), rows in `job_photos`. The app deletes the files when a booking is deleted (`owner_delete_booking` returns their paths).
- Batch 2 (0006): `bookings.started_at` (Start wash) and `bookings.checks` (ticked checklist item texts). The checklist itself is not stored: the app builds it from `PKG` (expanding "Everything in …"), the booking's add-ons and a final walk-round, so it follows the website's package contents. `customer_notes` (one saved note per mobile, shown via `booking_json.cust_note`, deleted with the customer's last booking). `owner_move_day` moves bookings in bulk; the `moved` message template goes with it. `owner_durations` feeds Analytics → Time per wash. Route uses Google Maps directions links (10 stops per link).
- Plans & societies (0007, owner screen `#plans`, page `#c/<id>`): `contracts` (kind plan|society, fixed `weekdays` + slot, price a month), `contract_vehicles` (society list), `contract_periods` (one month, paid once). `owner_contract_period` books the month's visits as ordinary bookings with `period_id`, `payment = 'covered'`, total 0, source plan|society; a society visit's `items` (its vehicles) is its checklist. A trigger keeps covered visits covered. `range_numbers` adds month payments (by `paid_at`) to Collected. Visits for months already created are not changed by later edits.
- Batch 4 (0008): washer pay (`staff.pay_car/pay_bike`, `payouts`, `bookings.payout_id`; Settings → Pay; washers see `staff_my_pay`), `expenses` with bill photos in Storage `job-photos/bills/…` (owner approves), `supplies` stock (any staff ± qty, owner edits list, Home warns at `low`), receipts (`staff_receipt` → `receipt.html?b=&k=`, noindex, no phone/address), `bookings.cancel_reason` via `staff_cancel`. Approved expenses and payouts are added to costs in `range_numbers`.
- Batch 5 (0009): `bookings.track_key` (random, every booking). `track.html?b=&k=` (noindex) shows the booking live and lets the customer move or cancel it until 2 hours before the slot (`slot_caps.starts`; full/closed slots refused; plan/society visits can't be changed online). Changes are logged in `booking_events` with actor_name `Customer` and show on Home/bell as "Changed online" (no phone alert for these yet). The Confirm template gets `{track_link}`; lines with an unfilled `{track_link}` are dropped. Cash handover: `cash_handovers` (amount + what the app expected); balance = cash jobs assigned to the washer (Paid in cash since `app_settings.cash_from`) minus handovers. `owner_due`/Home due count leave out plan/society customers; Home's count skips people reminded in the last 7 days.
- Left-over jobs (0010): `leftover_jobs()` = bookings still new/confirmed/on_way from the last 60 days before today. `staff_day(today)` returns them as `leftover` (Jobs shows "Left over from earlier days" on today only); `owner_attention().overdue` puts them at the top of Home's Needs attention as "Not finished".
- Rain warning on Jobs: browser fetches Open-Meteo (no key; only a central-Mumbai point is sent), cached 45 min in `vb.rain`; warns at ≥60% and ≥1 mm in a slot with open jobs.
- Light/dark switch uses the View Transitions API with an ink-blot mask from the tapped button (`themeSwap` in `src/ops.js`); falls back to an instant switch.
- Phone alerts: edge function `supabase/functions/push` (deploy via editor, Verify JWT off) makes and keeps its own VAPID key pair in `push_config` (service role only); `push_subs` per device; trigger `booking_push` calls the function through `pg_net` for website bookings with `push_config.hook_secret`; alerts go to active owners. Service worker `src/ops-sw.js` (no caching). iPhone needs the Home Screen app.
- Nightly backup: `.github/workflows/backup.yml` (repo is public): `pg_dump` (public schema + auth users) → gzip → gpg with `BACKUP_PASSPHRASE` → 30-day artifact. Secrets `SUPABASE_DB_URL` (session pooler) and `BACKUP_PASSPHRASE` live only in GitHub. Storage photos aren't backed up.
- Staff app offline queue: status taps and notes/calls/messages made without internet wait in localStorage `vb.queue` and are sent in order when back online. Photos and new bookings need internet.
- The customer is also handed off to WhatsApp with the booking prefilled. If Supabase can't be reached, the customer is asked to send the prefilled WhatsApp message instead (no Sheet fallback). The old Apps Script booking API (`google-apps-script/Code.gs`) is retired; `SITE.sheetUrl` is empty. Aniket replaced it in the "Vroombrite Bookings" Sheet with `google-apps-script/SheetCopy.gs`, which rewrites that Sheet's tabs from the database every night (read-only copy) using the key in Settings → Data & activity.
- Never put the Supabase secret/service_role key or database password in the repo or chat. Only the publishable key goes in `src/config.js`. New schema changes go in a new numbered migration file that Aniket runs in the SQL Editor.

## How the files fit
- **Edit sources in `src/`**, then run `python3 src/build.py`.
  - `src/pages/<slug>.html`: the body of each page. `@@slug@@` tokens become links. `@@CTA@@` inserts `src/pages/_cta.txt`.
  - `src/build.py`: page list, titles, meta descriptions, the shared header and footer (logo markup lives here).
  - `src/style.css`, `src/app.js`, `src/config.js`, `src/ops.js`, `src/ops.css` and `src/ops.webmanifest` are copied to the root on build. `config.js` loads before `app.js`/`ops.js` on every page.
- The build writes the root pages (`index`, `car-wash`, `bike-wash`, `detailing`, `subscription`, `societies`, `gallery`, `contact`, `book`, `review`, `ops`, the policy pages `privacy`, `terms`, `refunds`, and one `doorstep-car-wash-<area>.html` landing page per service area) plus `sitemap.xml`, `robots.txt` and `preview/index.html`.
- **Service areas live in `src/areas.json`** (name, slug, PINs, nearby areas). The build injects them into `app.js` (PIN check, area chips) and generates the area pages from `src/pages/_area.html`. To add an area, add it there and rebuild.
- `ops.html` + `src/ops.js` + `src/ops-guide.js` + `src/ops.css` is the **staff app** (no site header, `noindex`, blocked in robots.txt). Its layout and features follow Studio CRM (frosted-glass panels over soft brand-colour light, floating sidebar that folds, Ctrl K search, bell, light/dark, first-time tour, sign-in animation, paid confetti) in Vroombrite colours and fonts (Montserrat/Inter). Screens are hash routes: `#home` (owner), `#jobs`, `#bookings` (board with drag-and-drop + sortable table), `#b/<ID>` (booking page with journey line), `#customers`, `#plans`/`#c/<id>`, `#kit` (stock & bills, all staff), `#inbox`, `#analytics`, `#settings/<tab>` (Team, Pay…), `#help`. Phones get a slim top bar and a floating bottom tab bar. The build makes root `ops.js` = the price list block from `app.js` (`PKG`…`SIZE_LABEL`, one source of prices) + `ops-guide.js` + `ops.js`, and writes `version.json` (build id = hash of the shared files) for the "new version ready" bar; scripts and CSS carry `?v=<build>`.
  - Sign-in: Supabase Auth email/password, "Forgot password?" email (needs the Redirect URL set in Supabase), change own password. First user = owner.
  - Logins are managed in the app's Team screen through the edge function `supabase/functions/team-admin` (add, update incl. email/role, password, delete). It checks the caller with `staff_me` and does every database change through owner-only RPCs as the owner; only `auth.admin` calls use the service key, which Supabase gives the function. Deployed by pasting the file in Supabase → Edge Functions.
  - Roles: washer = Day, Bookings, New booking, Help; edits plate/notes only; their own added bookings are assigned to them. Owner = everything. `staff_*` RPCs need `is_staff()`, `owner_*` need `is_owner()`.
  - Booking history in `booking_events` (status, payment, edits, notes, calls, messages, assignment). Owner-only `audit_log` never stores customer details. WhatsApp wording in `message_templates` (owner edits; `{placeholders}`), team notice, offers (website reads amounts from `check_offer`), monthly `costs` for profit.
  - **Help guide rule:** every visible staff-app change updates `src/ops-guide.js` (its section + a `WHATS_NEW` line) in the same commit.
  - Renders from localStorage cache first, buttons update optimistically and roll back; polls every 30 s; "New booking" alert compares `created_at` with the newest one the phone has seen.
- `review.html?b=<booking ID>` is the customer feedback form. Reviews are saved to the database and appear on Home and Gallery only after the owner taps **Show on website** in the staff app's Inbox. The preview is a single-page, hash-routed copy used for Claude artifact previews and is git-ignored.
- Share previews (WhatsApp/Instagram/Facebook): every page has absolute Open Graph and Twitter tags built from `SITE_URL` in `src/build.py`, which must be updated when the custom domain goes live. Cards are `img/og-*.jpg` (1200×630; home, car, bike, detail, plans), and `OG_IMG` maps pages to cards. To redesign or regenerate them, run `src/share-cards/render.py`.
- **Do not hand-edit the root `.html`, `.css` and `.js` files.** The next build overwrites them.

## Decisions so far
- Home keeps the scroll-to-wash hero: muddy → foam → shine car crossfaded by a jet wipe as you scroll, built from three matching Canva images. The Dribbble-style hero was rejected.
- Separate car and bike booking journeys. Car bookings can add detailing treatments. A PIN check is required in step 2.
- Photos in `img/` are AI-generated (Canva). Aniket decided (6 Nov 2026) to use them for the first few months without any "illustrative" label, then replace them with real job photos under the same file names (landscape, about 1680×944). Copy must not claim they are real customer cars or results.
- Payment: **pay after the service (UPI/cash) is the primary/default option**. Online payment (UPI) is the secondary option for the starting phase. Aniket plans to make online payment primary once the brand is established. Razorpay comes later, with its own merchant account for this business, not Little Gasp's.
- Policies (privacy, terms, cancellation & refund) were added at launch. They contain policy decisions Aniket should confirm: the 2-hour free-cancel window, the ₹99 late-cancel/no-access visit fee, 5–7 working-day refunds and the 24-hour redo guarantee.
- Payment status is updated by staff in the staff app (Paid by UPI / Paid in cash). A `upi://` link gives no payment callback. Automatic "paid" status needs a gateway (Razorpay webhook → Supabase) later.
- Offers need a **minimum order of ₹299** (package + add-ons, before discount; `min` in `PROMOS`/`REFERRAL`), set so the cheaper bike washes stay profitable. Below the minimum, the offer stays attached but gives no discount, and the site tells the customer how much more to add.
- Offers: code `WELCOME50` (₹50 off the first wash), or the friend's mobile in "Referred by" (₹50 off for the new customer, plus ₹50 credit for the referrer once the friend's job is marked Done). Only one ₹50 discount per booking. Both are checked by the database (`check_offer`, and again inside `create_booking`, which decides the discount itself) before booking, and Confirm is disabled while the check runs. If the check is unreachable, the offer is shown provisionally and the database still refuses it at booking if not allowed. The amounts are placeholders. Keep `PROMOS`/`REFERRAL` in `src/app.js` in sync with the `offers` table.
- WhatsApp messages are one-tap (they open prefilled for a human to send), not automatic. Automatic sending needs Meta's WhatsApp Business Platform with approved templates, which is not set up.
- The nav shows Societies instead of Gallery; Gallery is in the footer.
- Prices are Claude's launch placeholders. Aniket will send final prices after discussing with his partner.
- Testing standard: check every page at phone (390px) and laptop (1440px) widths before calling a change done.
- Ops app moved from the PIN/Sheet version to Supabase (Nov 2026) because Apps Script was too slow (1–3 s per call). Aniket chose a new design for it rather than copying Studio CRM.
- Staff app v2 (Nov 2026): Aniket asked for Studio CRM's features, especially managing washers' logins, access and passwords from the app instead of the Supabase dashboard.
- Staff app look (6 Nov 2026): Aniket found the first staff design weak and asked to match Studio CRM's UI with more of its features; he chose Studio's layout in Vroombrite colours (not Studio's cream/gold).
